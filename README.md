## Запуск

1. Распакуй **весь архив** в постоянную папку, например `C:\Apps\Ritm`.
2. Нужен установленный **Python 3.10 или новее**. Если его нет,
   установи с https://www.python.org/downloads/windows/ и включи
   **Add python.exe to PATH**.
3. Дважды нажми **START_WINDOWS.cmd**.
4. Добавь первую задачу или нажми **Попробовать на примерах**.

В Edge/Chrome интерфейс открывается отдельным app-окном. Если их нет,
используется обычная вкладка браузера. Браузер служит интерфейсом;
Python-процесс отвечает за базу и фоновые напоминания.
Запуск не меняет Python или зависимости Dictor.

Первый список пустой. Кнопка примеров создаёт четыре настоящие задачи,
которые можно отредактировать или архивировать. Достижения и история
не подменяются демонстрационными цифрами.

## Сборка EXE из PowerShell

Распакуй содержимое патча в корень существующего проекта с заменой файлов:
рядом должны находиться `BUILD_WINDOWS.cmd`, `main.py` и папка `ritm`.

В PowerShell из этой папки выполни:

```powershell
.\BUILD_WINDOWS
```

Результат успешной сборки: **`dist\Ritm.exe`** — один файл со встроенными
HTML/CSS/JS и значками. Он запускается без установленного Python.
Edge/Chrome либо другой установленный браузер по-прежнему нужен для окна UI.

Для сборки нужны **Windows, 64-битный Python 3.10–3.14 и интернет** для
установки PyInstaller. Скрипт выбирает доступный Python, создаёт отдельное
окружение `.venv-build`, устанавливает `PyInstaller==6.22.3`, запускает
тесты и собирает приложение. Глобальные зависимости Python не меняются.
`BUILD_WINDOWS.cmd` работает из PowerShell без изменения ExecutionPolicy.

Последний этап автоматически запускает собранный EXE в изолированном
временном профиле, проверяет API, наличие файлов интерфейса и запись
задачи в SQLite, затем останавливает проверочный процесс. Сообщение
`BUILD OK` появляется только после успешной проверки. Исходные задачи
пользователя для проверки не используются. Трей и визуальное окно этой
проверкой не тестируются.

Запуск результата:

```powershell
.\dist\Ritm.exe
```

Приложение хранит данные в прежнем `%LOCALAPPDATA%\Ritm`. Перед переходом
с исходной версии заверши её через меню трея, чтобы открыть именно EXE.
После перемещения EXE включи автозапуск заново из нового расположения:
в реестр записывается постоянный путь к `Ritm.exe`, а не временная
папка распаковки PyInstaller.

Здесь сборка Windows EXE не выполнялась: среда подготовки патча — Linux.
Справочник: https://pyinstaller.org/en/stable/runtime-information.html

3. Выполни `.\BUILD_WINDOWS`, затем запусти `.\dist\Ritm.exe`.

База `%LOCALAPPDATA%\Ritm` сохраняется. Копирование исходников не меняет
ранее собранный EXE: для нового оформления обязательна пересборка.

## Настройка темы

Открой **Настройки → Настрой свой ритм**.

- Основа: **Неоновая**, **Ночная** или **Светлая**.
- Гаммы: **Океан**, **Аметист**, **Лес**, **Закат**; видимый спектр оттенка,
  насыщенность и яркость фона. Смена гаммы возвращает частные цвета на «Авто».
- Цвета элементов: акцент, фон окна, карточки, боковая панель, поля ввода,
  основной и вторичный текст, границы. Нажми на цветной образец для выбора;
  HEX вводить не требуется. **Авто** возвращает цвет текущей гаммы.
- Эффекты: включение и сила свечения, градиенты, границы панелей,
  скругление углов от 0 до 24 px.
- Предпросмотр применяется ко всем страницам. **Сохранить тему** записывает
  оформление в SQLite; **Отменить** возвращает сохранённый вид.
- **Сбросить** показывает исходную тему; для сохранения сброса также нажми
  **Сохранить тему**. Изменения во время записи остаются отдельным черновиком.

Явно выбранные цвета текста сохраняются без подмены. Если контраста не хватает,
форма показывает подсказку. Автоматические цвета подстраиваются под фон,
но противоположные по яркости пользовательские поверхности могут потребовать
ручного подбора. Старые профили получают новые параметры без потери задач.

Настройки построены по принципу оформления Omni: общая гамма и эффекты.
Референс: https://github.com/Klio-de-Janeiro/omni_reader/blob/main/dist/themes.js

## Исправления редактирования и загрузки интерфейса

- Нажми название задачи или **Изменить**. На узком экране остаётся заметная
  кнопка с карандашом, доступная мышью, клавиатурой и нажатием.
- Исправлены сохранение просроченной разовой задачи и перенос её даты без
  оставшегося старого ожидания. Будущую задачу можно перенести раньше.
- Введённое имя и несохранённое оформление не стираются фоновым опросом.
- Блок и статус Dictor скрыты из UI; API и Python-клиент оставлены для будущего
  подключения.
- Сервер загружает полный комплект ресурсов при запуске. Основной CSS
  включает оформление, основной JS — движок темы. Сборка сравнивает ресурсы
  внутри EXE с исходниками и проверяет MIME CSS/JS. При отсутствии файла
  запуск явно завершается ошибкой вместо частично работающего интерфейса.

В этой версии редактируются задачи и их заметки; редактора документов
PDF/DOCX и файлов с диска в Ритме нет.

## Исправление остановки Windows-сборки на тестах

Патч исправляет два дефекта проверок из присланного лога:

1. Тест запуска ожидал совпадения PID родительского процесса и приложения.
   В Windows виртуальное окружение Python может использовать redirector
   с другим PID. Теперь проверяются новая сессия и работающий API.
   Добавлен тест с отдельным процессом-родителем и ожидание освобождения
   блокировки временного профиля после остановки.
2. Контекст SQLite в тесте новой схемы завершал транзакцию, но не закрывал
   соединение. Теперь оно закрывается явно через `contextlib.closing`,
   чтобы Windows могла освободить временный файл базы.

Применение: заверши запущенный Ритм через меню трея, распакуй содержимое
патча в папку проекта с заменой файлов и снова выполни:

```powershell
.\BUILD_WINDOWS
```

Результат: `dist\Ritm.exe`. В патче сохранены все проверки сборки.
Тема включается в EXE при пересборке вместе с остальными ресурсами UI.

Справочники:
https://docs.python.org/3/library/venv.html
https://docs.python.org/3/library/sqlite3.html#how-to-use-the-connection-context-manager

## Как пользоваться

- Быстро добавить: введи название в строку **Что сделаем сегодня?** и нажми Enter.
- Полная форма: **Новая задача**, клавиша **N** на английской раскладке
  или значок настроек справа от строки добавления.
- Повторения: один раз, каждый час / 3 / 5 / 8 / 12 часов, каждый день,
  раз в 3 дня, по будням, раз в неделю и раз в месяц.
- Для напоминания включи переключатель и укажи время. Само заполнение
  времени без переключателя задаёт время задачи без системного уведомления.
- Нажми кружок слева от задачи, чтобы выполнить её. Она уйдёт из фильтра
  **В работе** и появится в **Мой прогресс**. Вернуть можно через **Отменить**.
- **Календарь** позволяет открыть план любого дня.
- Название задачи или **Изменить** открывают редактор. **В архив** останавливает повторения,
  сохраняя предыдущие выполнения.
- Колокольчик сверху открывает журнал: задачу можно выполнить или
  отложить на 10 минут. Через API доступны также 5, 15, 30 и 60 минут.
- **Настройки**: имя, оформление, звук, напоминания, автозапуск,
  экспорт всех данных и полное завершение приложения.

## Что значит ежедневное обновление

У каждой повторяющейся задачи есть своё расписание. При наступлении
нового местного дня создаётся новая запись этого дня. Вчерашняя отметка
остаётся в истории и не сбрасывается в базе.

Если приложение несколько дней было остановлено, при запуске оно создаст
пропущенные записи по расписанию. Пропущенные ежедневные напоминания
не вызывают лавину старых уведомлений: проверяется текущий день.
Просроченная разовая задача остаётся в сегодняшнем плане, пока не будет
выполнена или архивирована. Если она ещё ни разу не напоминала,
планировщик напомнит о ней после запуска.

Редактирование меняет незавершённые задачи начиная с сегодняшнего дня
и просроченную разовую задачу. Выполненные записи и прошлые повторения
сохраняют свои названия и категории.
Для отмены выполнения используйте **Мой прогресс → Отменить**.

XP вычисляется по сохранённым выполнениям: **10 XP за задачу**.
Уровень повышается каждые 100 XP. Повторное нажатие не даёт лишних очков.
Отмена выполнения вычитает соответствующие очки.
Серия — число дней подряд с хотя бы одним фактическим выполнением.
Если сегодня пока ничего не сделано, вчерашняя серия сохраняется до конца дня.
Карта активности использует дату фактической отметки. Недельный мини-график
показывает выполненные задачи по запланированным датам.

## Трей и фоновые напоминания

Трей — область небольших значков возле часов Windows. Значок Ритма
может быть скрыт за стрелкой **^**. Нажатие открывает окно, правая кнопка
показывает **Открыть Ритм / Завершить Ритм**.

**Закрытие окна не выключает Python-процесс:** пока он работает,
планировщик проверяет напоминания каждые 5 секунд. Для остановки
используй меню трея или **Настройки → Завершить приложение**.
Для запуска после входа в Windows включи соответствующую настройку.
Автозапуск добавляет только собственную запись `Ritm` в `HKCU\...\Run`.
Перед переносом исходной папки выключи автозапуск, затем включи снова
из нового расположения.

Ограничения этой версии:

- При выключенном компьютере, выходе из аккаунта или во время сна
  Python-код не выполняется. После пробуждения наступившие напоминания
  обнаруживаются следующей проверкой. Будильник не пробуждает компьютер.
- Windows может скрыть системное уведомление из-за **Не беспокоить**,
  политик уведомлений или других настроек ОС. Событие всё равно остаётся
  в журнале Ритма. Для проверки есть **Проверить уведомление**.
- Это Shell-уведомления из трея; кнопки «Выполнено / Отложить» находятся
  в приложении, а не внутри системного баннера.
- Android-приложение и прямая синхронизация в доверенной домашней сети
  описаны в ANDROID_GPT_RU.md. Облачная синхронизация, Google OAuth и Google
  Calendar пока не подключены. Для локальных задач аккаунт и интернет не нужны.

## Данные

Windows: `%LOCALAPPDATA%\Ritm`.

- `ritm.sqlite3` — задачи и история;
- `api.key` — приватный ключ для Dictor;
- `runtime.json` — сведения о работающем процессе и приватная UI-сессия;
- `ritm.log`, `launcher.log` — диагностика;
- `browser-profile` — отдельный профиль app-окна.
- `mobile-sync.json` — параметры обмена, идентификатор базы и секретный код телефона.

Не публикуй `api.key`, `runtime.json` и `mobile-sync.json`. Они не включаются в экспорт.
Данные не находятся в папке исходников, поэтому замена приложения
не заменяет базу. Для ручной полной резервной копии сначала заверши Ритм
и скопируй весь каталог данных. JSON-экспорт доступен в настройках;
автоматический импорт JSON пока не реализован.

Системный часовой пояс берётся с компьютера. Отдельного календарного
часового пояса в этой версии нет. При переводе часов повтор уже доставленного
напоминания не создаётся. Перенос компьютера в другой часовой пояс требует
проверки местных времён задач.

## Dictor

API уже готов, но код самого Dictor в этот архив не входил и не изменялся.
Инструкция: **integrations/DICTOR_API.md**.
Клиент: **integrations/dictor_client.py**.
Блок подключения скрыт до следующего этапа. Клиент может прочитать
адрес и токен из локального профиля через `RitmClient.from_local_profile()`.

Ритм принимает структурные команды от Dictor. Распознавание речи,
потоковое управление микрофоном и определение намерения Qwen остаются
в отдельном проекте Dictor.

## Разработка и проверка

```powershell
cd C:\Apps\Ritm
py -3 -m unittest discover -s tests -v
py -3 main.py
```

Если 8768 занят:

```powershell
py -3 main.py --port 8769
```

Для изолированного теста без открытия браузера:

```powershell
py -3 main.py --background --no-tray --port 0 --data-dir .\test-data
```

Фактический порт будет записан в `test-data\runtime.json`.
Два процесса с одной базой одновременно не запускаются. Второй обычный
запуск открывает интерфейс уже работающего приложения.

Для Linux возможен `python3 main.py`, но эта версия реализует системный
трей и уведомления именно для Windows. В других ОС остаётся журнал в UI.

| `START_WINDOWS.cmd`, `launcher.py` | Тихий запуск без установки пакетов |

Код и API проверены автоматическими тестами. Нативный трей, Windows-баннеры
и `.cmd` требуют отдельной проверки на Windows: среда сборки — Linux.

## Крупный текст

Шрифты интерфейса увеличены примерно на 25%; мелкие подписи подняты
до минимума 14 px, включая узкие окна. Кнопки, карточки и формы допускают
перенос текста. Название приложения — «Ритм», самостоятельные подписи
начинаются с заглавной буквы. Пользовательские задачи не переписываются.
После замены файлов заверши старый процесс через трей или настройки,
выполни `.\BUILD_WINDOWS` и запусти новый `dist\Ritm.exe`.

## Единый значок из Ritm.png

`Ritm.png` лежит в корне проекта рядом с `README.md`, `BUILD_WINDOWS.cmd`
и папкой `dist`. В патче уже находится сгенерированный неоновый значок.
Можешь заменить его своим PNG (не менее 256×256, желательно квадратным).

1. Полностью заверши Ритм через настройки или трей.
2. Выполни `.\BUILD_WINDOWS`. PNG автоматически преобразуется в ICO с размерами
   16/20/24/32/40/48/64/128/256 px и веб-значок 512×512. Оба встраиваются в EXE.
3. Запусти **INSTALL_WINDOWS.cmd** двойным нажатием или через
   `.\INSTALL_WINDOWS`. Будут созданы ярлыки **Ритм** в меню «Пуск»
   текущего пользователя и на его рабочем столе. Права администратора не нужны.
4. Найди **Ритм** в «Пуск» → правая кнопка → **Закрепить на панели задач**.
   Старый закреплённый ярлык сначала открепи, чтобы Windows не показывала
   сохранённый старый значок.

Ярлыки ссылаются на `dist\Ritm.exe` в текущей папке проекта. Оставь папку
в постоянном месте. Если перенесёшь её, снова запусти `INSTALL_WINDOWS.cmd`.
После сборки сам EXE переносим и содержит все значки — PNG рядом с ним
не требуется. Простая замена PNG без пересборки не меняет установленный EXE.

Значок используется в EXE/Проводнике, трее и системных напоминаниях,
в интерфейсе, favicon и новых ярлыках. Окну Edge/Chrome из выделенного профиля
Ритма назначаются icon, AppUserModelID и команда повторного запуска EXE;
этот же AppUserModelID записывается в ярлыки. При использовании обычного
браузера вместо Edge/Chrome значок вкладки обновляется, но панель задач
может оставаться значком самого браузера.

Монитор проверяет принадлежность окна выделенному профилю; остальные
окна браузера не изменяются. Для проверки процесса используется встроенный
Windows PowerShell. Выполнение скриптов из файлов и изменение ExecutionPolicy
не требуются. Закрепление выполняется самим пользователем через оболочку Windows.

В Linux проверены ресурсы и преобразование изображения; нативное отображение
значков, установка ярлыков и группировка панели задач требуют проверки Windows.
Документация Windows: https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-id
