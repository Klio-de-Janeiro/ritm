# Проверка версии 0.3.1

Дата: 16 октября 2026. Linux, Python 3.12, Node.js 24, Java 17.

- Основной набор: 81 сценарий, 80 пройдены; один MCP-сценарий пропускается без необязательного SDK. С официальным SDK 1.30.0 отдельно пройдены все 7 тестов GPT, включая этот сценарий.
- Настоящий SDK-клиент запустил STDIO-сервер, выполнил initialize и tools/list, получил дату ноутбука и создал задачи через локальный HTTP API. Проверены повтор UUID без дубля, все новые интервалы и отказ от строкового boolean вместо true/false. Секреты не включены в результаты.
- Проверены все часовые интервалы, непрерывный 5-часовой отсчёт через полночь, возобновление после перезапуска без пачки сигналов, остановка сигналов после выполнения, snooze и месяцы разной длины.
- 10 тестов Android-модели на JVM пройдены. Все Java-классы скомпилированы против Android API 35 / WorkManager 2.9.1, с техническим R-стабом для ресурсов.
- UI-модель DOM проверила выбор часового интервала, обязательное время и обработчик Esc: при открытом диалоге нативная команда не отправляется, без диалогов вызывается защищённый локальный API. Авторизация и запрет постороннего Origin этого API проверены отдельно.
- Протокол синхронизации повышен до 2. Тесты обмена, квитанций, конфликтов и сохранности SQLite проходят.

Не проверены здесь: фактический SendInput/F11 в Windows, полная сборка Windows EXE и Android APK/Android Lint, уведомления на физическом телефоне. Не выполнено подключение к аккаунту ChatGPT пользователя: настройки локального MCP нужно сохранить на его ноутбуке и проверить из ChatGPT. Успех в SDK-тесте не означает, что инструмент уже установлен в аккаунт.

Команды: `python3 -m unittest discover -s tests -q`; с установленным requirements-gpt.txt — `python -m unittest discover -s tests -p test_gpt.py -q`. Сборка APK сама запускает JUnit и lintRelease.

# Проверка версии 0.3.0

Дата: 16 октября 2026. Среда: Linux, Python 3.12, Node.js 24, OpenJDK 17.

- 67 автоматических проверок Python/JS — пройдены (`python3 -m unittest discover -s tests -q`). Включают прежние 55 проверок и 12 сценариев синхронизации/импорта/полноэкранного запуска.
- 8 JUnit-тестов Android-модели — пройдены на JVM с org.json 20240303: офлайн-очередь, повторное выполнение, правка во время запроса, сохранение конфликтов, неполная квитанция, неизменность выполненной истории, валидация плана, расписание.
- Все Java-классы Android скомпилированы javac 17 против официального Android API 35 и WorkManager 2.9.1. Для ссылок на ресурсы использован технический R-стаб; aapt/DEX/APK этим не проверяются.
- Межплатформенный цикл: настоящая Java-модель создала очередь «создать → выполнить → отменить → изменить», Python SyncEngine применил её к SQLite, Java приняла ответ. Повтор после потери ответа не создал дубликатов.
- Проверены синтаксис JavaScript, XML Android, уникальность HTML id и соответствие селекторов мобильного UI.
- Проверена загрузка нового desktop-бандла через настоящий HTTP-сервер; companions.js включён в основной app.js и доступен как статический ресурс.

**Не проверены в этой среде:** полная сборка Gradle/APK и Android Lint, установка на реальный телефон, системные Android-уведомления/Doze, поведение клавиатуры и полноэкранного окна на реальных устройствах, Windows-брандмауэр и LAN двух устройств. Сборка Windows EXE также требует Windows. Команда BUILD_ANDROID запускает JUnit, lintRelease, assembleRelease и apksigner перед сообщением об успехе.

Синхронизация включается явно и предназначена для доверенной частной сети: HTTP без TLS, отдельный токен, отдельный порт, запрет браузерного Origin, ограничения размера/числа команд, квитанции в одной транзакции с изменениями. Основной локальный API продолжает проверять Host/Origin и авторизацию.

# Проверка версии 0.2.0

Дата: 15 октября 2026. Среда: Linux, Python 3.12, Node.js 24.

**51 автоматический тест — пройден после исправления редактирования и расширения оформления.**

Команда: `python3 -m unittest discover -s tests -v`.

Проверены:

- ежедневное обновление, пропущенные дни и сохранность истории;
- ежедневные, недельные и будние расписания;
- защита от выполнения будущих задач;
- повторное выполнение без повторных XP и отмена отметки;
- реальная серия по датам выполнения;
- наступление напоминания, отложенное напоминание и перезапуск базы;
- отключение уведомлений, архив и отсутствие лавины старых повторений;
- одновременные повторы команды Dictor и конфликт идентификаторов;
- настоящий HTTP API и отдельный Python-клиент Dictor;
- UI-cookie, bearer-доступ, запрет чужого Origin/Host и не-JSON-команд;
- загрузка всех статических файлов и календаря;
- экспорт без токенов и приватных runtime-данных;
- запуск отдельного процесса, запрет второго экземпляра,
  остановка через API и восстановление прогресса после перезапуска.
- автозапуск EXE по постоянному пути с пробелами, без ссылок на распаковку;
- сохранение автозапуска исходной версии через pythonw;
- протокол автоматической проверки сборки на настоящем исходном HTTP-сервере;
- отказ от попытки выдать сборку Linux за Windows EXE.
- запуск приложения с PID, отличающимся от PID родительского процесса;
- освобождение блокировки временного профиля после остановки;
- миграция старой базы к настройкам темы с сохранением задач;
- сохранение темы, HEX-цвета и интенсивности свечения после перезапуска;
- отклонение некорректных настроек до записи других полей;
- передача оформления через настоящий HTTP API;
- JS-движок: 24 сочетания темы/цвета, контраст акцентного текста,
  сохранённый кэш, предпросмотр без сохранения и повреждённый localStorage.

Дополнительно:

- `node --check ritm/web/app.js` — без синтаксических ошибок;
- `node --check ritm/web/theme.js` — без синтаксических ошибок;
- HTML: 127 уникальных ID, 74 ссылки JavaScript на ID разрешены;
- все 26 локальных SVG-символов и ссылки на них присутствуют;
- Windows `.cmd` сохранены в ASCII с CRLF.

Не проверены в этой среде:

- визуальный рендеринг интерфейса в настоящем браузере;
- нативный Windows message loop, меню трея и Shell-уведомления;
- Edge/Chrome app-окно, автозапуск HKCU и фактический запуск `.cmd` в Windows;
- вызов из существующего проекта Dictor: его исходников в поставке не было.
- фактическая сборка Windows EXE и запуск bootloader PyInstaller.

Тестовый клиент Dictor подключался к настоящему API Ритма на loopback;
это проверяет контракт, но не заменяет подключение обработчика голоса Dictor.

Получен лог Windows: сборка ранее остановилась на тестах PID и закрытия
SQLite. Оба дефекта исправлены; регрессионные проверки выполнены в Linux.
Повторная сборка Windows и визуальная проверка новых тем здесь не выполнялись.
Node.js нужен только для необязательного теста JS-движка; если его нет,
эта проверка пропускается, сборка EXE продолжает проверять Python/API.

## Регрессии 0.2.0

- Редактирование просроченной разовой задачи меняет видимую запись и напоминание.
- Перенос просроченной и будущей разовой задачи не создаёт дубликат ожидания.
- Все поля редактора проходят цикл PATCH → GET через настоящую UI-cookie.
- Настройки гаммы, все пользовательские цвета и эффекты сохраняются после
  создания нового Store; некорректные данные отклоняются атомарно.
- Основные CSS/JS содержат оформление; отсутствующий файл темы явно блокирует
  старт. HTTP-кэш отключён; проверены MIME и порядок движка темы перед UI.
- Протокол smoke-test сборки сравнивает байты встроенных ресурсов с исходниками.
- Node VM с моделью DOM проверяет обработчики: открытие и сохранение задачи,
  перенос даты раньше, имя после blur/polling, предпросмотр/сохранение/отмена/
  сброс темы и ввод новых изменений во время незавершённого сохранения.
  Это тест логики событий, не полноценный браузерный или визуальный тест.
- JS-движок дополнительно проверяет спектр, произвольные фоны и текст,
  режим «Авто», выключение эффектов и предупреждение о низком контрасте.

Chromium в среде отсутствует; загрузить браузер не удалось. Визуальную
проверку новых контролов и нативного выбора цвета необходимо выполнить
в Edge/Chrome на Windows. EXE и Win32-функции в Linux не запускались.

На скриншоте видны неприменённые стили темы. Точную причину на компьютере
пользователя по одному скриншоту установить нельзя. Объединение ресурсов,
проверка их полноты и явное завершение старого процесса перед обновлением
устраняют зависимость UI от отдельного запроса темы и смешения версий.

## Значок Ritm.png и ярлыки

Добавлен корневой PNG и автоматическое преобразование перед сборкой;
Pillow нужен только в окружении сборки. Новый ICO содержит девять размеров
с альфа-каналом; icon.png используется UI и favicon, icon.ico — EXE и треем.
Проверяются повторная замена PNG, прозрачность, размеры, отказ при отсутствии
и слишком маленьком изображении, MIME/байты PNG через настоящий HTTP.

INSTALL_WINDOWS.cmd запускает явную команду EXE --install-shortcuts.
Команда использует Known Folders и COM IShellLink/IPropertyStore для
ярлыков текущего пользователя. Данные и автозапуск не затрагиваются.
Нативный монитор выбирает HWND по заголовку, классу Chromium и PID,
проверенному по точному пути browser-profile через Win32_Process.
Окну и ярлыкам задан один AppUserModelID. Монитор не запускает PowerShell,
когда не обнаружено нового подходящего окна.

Win32/COM, PowerShell-поиск процесса и реальное закрепление в панели задач
в Linux не выполнялись. Нет утверждения о проверке всех значков на Windows.
