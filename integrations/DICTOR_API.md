# Подключение Dictor к Ритму

Исходников Dictor в этом комплекте нет: изменён только новый проект Ритм.
В Ритме уже есть HTTP API и Python-клиент. Вызов клиента необходимо добавить
в обработчик намерений существующего Dictor. Whisper/Qwen здесь не запускаются.

## Поток команды

Микрофон → Whisper в Dictor → Qwen/маршрутизатор в Dictor →
проверенный JSON → Ритм → SQLite → планировщик → Windows-уведомление.

Передавай финальный результат распознавания. Частичные гипотезы Whisper
не должны создавать новые задачи. Если отправка повторяется, используй
тот же `request_id` и то же содержимое команды. При изменённом содержимом
с тем же идентификатором API ответит HTTP 409.

Ритм не исполняет shell-код, Python-код или произвольные инструменты из ответа
LLM. Пока поддержаны только `task.create` и `task.complete`.
Неопределённое намерение или недостающее время нужно уточнить в Dictor.

## Адрес и доступ

- По умолчанию: `http://127.0.0.1:8768/api/v1`.
- При ручной смене порта: актуальное значение находится в `runtime.json`.
- Заголовок: `Authorization: Bearer <токен>`.
- Блок Dictor скрыт в UI версии 0.2.0 до этапа подключения.
- Локальный токен хранится в `%LOCALAPPDATA%\Ritm\api.key`;
  `RitmClient.from_local_profile()` читает его автоматически.
- Для того же пользователя Windows клиент может прочитать настройки сам.
- CORS отключён: этот API предназначен для локального Python-процесса Dictor.
- Ключ и runtime-файл приватны. Не добавляй их в Git, логи и запросы к LLM.

Скопируй `dictor_client.py` в пакет интеграций своего Dictor. Он независим
от остальных исходников Ритма и не требует установки зависимостей.

## Пример из Dictor

```python
from datetime import datetime, timedelta
from integrations.dictor_client import RitmClient

client = RitmClient.from_local_profile()
tomorrow = (datetime.now() + timedelta(days=1)).date().isoformat()

# Бери ID финального высказывания из Dictor; сохраняй при повторной отправке.
result = client.create_task(
    "Позвонить в деканат",
    request_id="dictor-final-utterance-20261015-0001",
    start_date=tomorrow,
    time="10:00",
    reminder=True,
    category="Учёба",
)
```

Функцию клиента вызывай в рабочем потоке Dictor, чтобы HTTP-запрос
не блокировал запись микрофона и интерфейс. Тайм-аут клиента — 8 секунд.
При транспортной ошибке допускается повтор с прежним ID.

## JSON-команда создания

```json
{
  "action": "task.create",
  "request_id": "stable-final-utterance-id",
  "task": {
    "title": "30 минут машинного обучения",
    "notes": "Одна тема и один небольшой эксперимент",
    "start_date": "2026-10-16",
    "recurrence": "daily",
    "time": "18:00",
    "reminder": true,
    "category": "Учёба",
    "priority": "normal"
  }
}
```

Отправляй на `POST /api/v1/commands` с `Content-Type: application/json`.
`start_date` — местная календарная дата компьютера пользователя;
пример выше нужно заменить на дату нужного напоминания.
Без `start_date` используется сегодня. Прошлое начало новой задачи запрещено.

| Поле | Допустимые значения |
| --- | --- |
| `title` | Непустая строка, до 200 символов |
| `notes` | Строка, до 2000 символов; необязательна |
| `recurrence` | `once`, `hourly`, `every_3_hours`, `every_5_hours`, `every_8_hours`, `every_12_hours`, `daily`, `every_3_days`, `weekdays`, `weekly`, `monthly` |

Часовые варианты требуют `reminder: true` и `time`. Они отсчитываются от
`start_date` и `time`, повторяются до выполнения одной записи дня и снова
действуют на следующий день. `monthly` сохраняет число начала, используя
последний день короткого месяца. Пример голосового подключения ChatGPT:
GPT_SETUP_RU.md.
| `category` | `Работа`, `Учёба`, `Здоровье`, `Личное` |
| `priority` | `low`, `normal`, `high` |
| `time` | `HH:MM` или `null` |
| `reminder` | `true` требует заполненного `time` |
| `request_id` | Строка от 1 до 128 символов, уникальная на финальную команду |

`weekly` повторяется в день недели из `start_date`.
`weekdays` — с понедельника по пятницу, не раньше даты начала.
Для точного относительного времени вычисли дату/время до отправки;
API не разбирает русские выражения вроде «через час».

## Выполнение задачи

Получить список: `GET /api/v1/state` или `GET /api/v1/state?date=2026-10-16`.
Каждый элемент `tasks` содержит `id` конкретного дня и `task_id` расписания.
Для выполнения нужен **`id` записи дня**, не UUID шаблона.

```json
{
  "action": "task.complete",
  "occurrence_id": 12,
  "completed": true
}
```

Повторный `completed: true` не начисляет повторных XP.
`completed: false` отменяет отметку. Будущие задачи выполнить нельзя.
При нескольких похожих названиях Dictor должен уточнить выбор,
а не отмечать первое совпадение автоматически.

## Остальные методы

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка процесса без токена |
| GET | `/state?date=YYYY-MM-DD` | Задачи дня, история, прогресс |
| GET | `/calendar?month=YYYY-MM` | Календарь на шесть недель |
| GET | `/tasks` | Активные расписания |
| POST | `/tasks` | Создать; поддержан `Idempotency-Key` |
| PATCH | `/tasks/{task_id}` | Изменить расписание |
| DELETE | `/tasks/{task_id}` | Архивировать, JSON-тело `{}` |
| POST | `/occurrences/{id}/complete` | `{ "completed": true }` |
| POST | `/occurrences/{id}/snooze` | `{ "minutes": 10 }` |
| PATCH | `/settings` | Изменить пользовательские настройки |
| GET | `/export` | Экспорт без секретов API |

Время системное, локальное. Настройки конкретных задач хранятся независимо
от включателя всех напоминаний. Если глобально выключить уведомления,
при повторном включении текущие наступившие задачи будут проверены заново.

## Куда встроить вызов в Dictor

После финальной транскрипции и классификации Qwen:

1. Проверить, что действие — создание/выполнение задачи.
2. Проверить дату, время, повторение и уверенность распознавания.
3. Сформировать JSON и передать его `client.execute(command)` в worker.
4. Показать в Dictor успех или понятную ошибку API.

Qwen не нужен ключ API: его добавляет только Python-клиент.
Архив не содержит автоматического изменения чужого проекта Dictor.
